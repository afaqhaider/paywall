Entitlements, licensing, devices, and webhooks — from your own backend.

A small, dependency-free Node.js client for the platform's API-key-authenticated runtime endpoints. Answer “can this customer do X” in one call, validate a license key someone typed in, register a device, and verify inbound webhooks — without hand-rolling HTTP.

01 · Setup

Quickstart

One client, four resource groups. Configure it once with your API key and the platform's base URL.

import { PaywallSDK } from "sszentronics-sdk";

const sdk = new PaywallSDK({
  apiKey: process.env.PLATFORM_API_KEY!,  // Dashboard -> API Keys
  baseUrl: process.env.PLATFORM_API_URL!, // e.g. https://api.yourdomain.com
});
i
Server-side only. This SDK is authenticated with a secret API key — it must run in your backend, never shipped to a browser.

03 · Reference

Entitlements & usage

Wraps apps/api/src/entitlements/public-runtime.controller.ts — new in this SDK’s release. RuntimeAuthorizationService was already built as, in its own words, “the runtime SDK surface,” but had no API-key-authenticated route until now. Requires an application-scoped API key.

GET/public/runtime/entitlements/:keysdk.entitlements.check(key)

Is this entitlement key allowed for your application right now? Returns { allowed, numberValue, textValue, isUnlimited }.

const { allowed } = await sdk.entitlements.check("advanced-reports");
if (!allowed) throw new Error("Not entitled to this feature");
GET/public/runtime/entitlements/:key/usagesdk.entitlements.getUsage(key)

Current usage/limit/remaining for a metered key. Returns { used, limit, remaining, isUnlimited }.

POST/public/runtime/entitlements/:key/incrementsdk.entitlements.incrementUsage(key, amount?)

Records usage. Throws SdkApiError (403) if this would exceed the limit — enforced server-side inside a transaction, never trust a client-side count.

POST/public/runtime/entitlements/:key/decrementsdk.entitlements.decrementUsage(key, amount?)

Reverses previously recorded usage — a refund, an undone action. Floors at zero.

03 · Reference

License keys

POST/public/runtime/license-keys/validatesdk.licenseKeys.validate(key)

Validates a license key a customer typed in — activation status, expiry, and activation-limit checks included. Never throws for an invalid key; check .valid.

const result = await sdk.licenseKeys.validate(userEnteredKey);
if (result.valid) {
  console.log(result.licenseId, result.status, result.expiresAt);
} else {
  // "not_found" | "inactive" | "expired" | "activation_limit_reached"
  console.log("Invalid:", result.reason);
}

03 · Reference

Devices

POST/public/devicessdk.devices.register(input)

Registers — or re-checks-in — a device. Upserts on deviceId, safe to call on every app start. If licenseId is set and that license has a deviceLimit, a genuinely new device enforces it; an already-known device re-checking in is never rejected.

const device = await sdk.devices.register({
  deviceId: "stable-client-generated-id",
  platform: "DESKTOP", // IOS | ANDROID | WEB | DESKTOP | OTHER
  licenseId: license?.licenseId,
});

Audited under a dedicated ApiKeySystemActorService so API-key-triggered writes are distinguishable in audit history from payment-webhook-triggered ones.

03 · Reference

Webhooks

Verifies and parses inbound webhooks, matching webhook-dispatch.service.ts’s signing scheme: HMAC-SHA256(secret, rawBody), sent as X-Webhook-Signature: sha256=….

import { constructWebhookEvent } from "sszentronics-sdk";

// Express — MUST use the raw body, not an already-parsed one
app.post("/webhooks/platform", express.raw({ type: "application/json" }), (req, res) => {
  const event = constructWebhookEvent(
    req.body.toString("utf8"),
    {
      signature: req.header("X-Webhook-Signature"),
      eventType: req.header("X-Webhook-Event"),
      deliveryId: req.header("X-Webhook-Delivery-Id"),
    },
    process.env.PLATFORM_WEBHOOK_SECRET!,
  );

  switch (event.eventType) {
    case "subscription.updated":
      // handle event.payload
      break;
  }
  res.sendStatus(200);
});
!
Hard-fails by design constructWebhookEvent throws SdkConfigError if the signature is missing, malformed, or doesn’t match — the same pattern as Stripe’s constructEvent — so a handler can’t accidentally process an unverified payload.

Error handling

ErrorThrown whenCarries
SdkApiErrorAny non-2xx API response.status, .body
SdkConfigErrorClient-side misuse — missing config, bad webhook signature.message
 
try {
  await sdk.entitlements.incrementUsage("api-calls");
} catch (err) {
  if (err instanceof SdkApiError && err.status === 403) {
    // over limit — prompt to upgrade
  }
  throw err;
}
